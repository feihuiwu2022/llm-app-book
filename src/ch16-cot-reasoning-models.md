# 16 CoT 与推理模型：让模型多想几步

## 从一个问题开场

第 3 章的探针四里有一个现象：同一批多步应用题，要求"只输出最终数字"时错得多，要求"一步一步计算"时错得少。

模型没换，题目没换，只是允许它把中间步骤写出来。为什么写出来就能对？

这个现象叫思维链，英文 Chain of Thought，简称 CoT。它是"改推理过程"这一行里最基础的技术，后面的 ReAct、规划、反思都建立在它之上。

## 掰开：为什么写出来就能对

回到第 2 章讲的生成方式：模型一次只生成一个 token，生成每个 token 时能看到前面的全部内容，包括它自己刚写的。

拿第 3 章那道滤芯题来看。

**直接答**。模型在"答案："之后必须立刻写出一个数字。从题目到这个数字，中间的四步推导全都要在生成这一个 token 的那一次计算里完成。模型一次计算能做的事是有限的，层数固定，没有草稿可打。

**分步答**。模型先写"三年共 36 个月，行驶 36 × 1500 = 54000 公里"。这句话写出来之后，就成了输入的一部分。接下来生成下一步时，54000 这个数就摆在眼前，不需要重新推。

| | 直接答 | 分步答 |
|---|---|---|
| 中间结果存在哪 | 无处可存 | 写在输出里，成为后续的输入 |
| 每次生成要完成的推理 | 全部步骤 | 一小步 |
| 输出长度 | 一个数 | 几行文字 |

**写出来的文字就是模型的草稿纸。** 模型没有别的工作记忆，它唯一能"记下"中间结果的地方就是自己的输出。

## 掰开：三种用法

### 一、提示词里要求

最简单的形式是在问题后面加一句"请一步一步思考"。更可控的写法是规定输出结构：

```text
请先在 <思考> 标签里逐步分析，再在 <答案> 标签里只写最终结果。
```

好处是程序可以把两部分分开处理：思考部分留作日志，答案部分交给下游。

### 二、给带推理过程的示例

在少样本示例里，不只给"问题和答案"，而是给"问题、推理过程、答案"。模型会模仿这种写法。这是思维链最初被提出时的形式。

### 三、多次作答取多数

同一道题让模型独立作答多次，每次都带推理过程，最后取出现次数最多的答案。这叫自洽性投票。

手算它为什么有效。假设是判断题，单次正确率 0.7，每次作答相互独立，做 3 次取多数：

- 3 次全对：0.7³ = 0.343
- 恰好对 2 次：3 × 0.7² × 0.3 = 0.441
- 多数正确的概率 = 0.343 + 0.441 = **0.784**

做 5 次取多数，同样的算法得到约 0.837。

正确率从 0.70 提到 0.78、0.84，代价是 3 倍、5 倍的费用。还要注意前提：单次正确率要高于一半，并且各次的错误不是同一种。如果模型每次都错在同一个地方，投多少次票都没用。

## 掰开：推理模型

上面这些都要靠提示词去引导。推理模型把"先想后答"做成了模型的内置行为：它在给出回答之前，先自动生成一段思考内容，再基于这段思考写最终回复。

从调用方看到的实物形态：

| | 普通模型 | 推理模型 |
|---|---|---|
| 一次输出包含 | 回复 | 思考内容 + 回复 |
| 思考内容是否可见 | 不适用 | 因厂商而异：完整返回、返回摘要、或不返回 |
| 可调参数 | 无 | 通常可以设置思考的预算或力度 |
| 计费 | 输入 + 输出 | 思考内容按输出 token 计费 |

本质上它仍然是思维链：思考内容也是一个 token 一个 token 生成的，也占用上下文窗口。区别在于这种行为是训练出来的，不需要你在提示词里要求，而且通常想得更长、更有章法。

### 资源账本：思考的代价

一个问题，回复 200 token。用推理模型时它先思考了 2,000 token。

- 输出 token 从 200 变成 2,200，**输出费用是原来的 11 倍**
- 按每秒 50 个 token 的输出速度，用户多等 2,000 ÷ 50 = **40 秒**才看到第一个字

第 2 章说过输出比输入贵。思考全部算输出，所以推理模型的费用和延迟主要花在思考上。预算要按任务难度设置：简单任务给少量甚至关闭，困难任务再放开。

## 什么任务值得多想

| 值得 | 不值得 |
|---|---|
| 多步计算、逻辑推导 | 查一个事实 |
| 需要比较多个方案 | 格式转换、信息抽取 |
| 规划一个复杂任务的步骤 | 简单分类 |
| 调试、找原因 | 闲聊 |
| 答错代价高 | 对延迟敏感 |

判断方法还是第 3 章的探针四：在自己的任务上对比"直接答"和"分步答"的正确率。差距不大，就不必为思考付费。

## 为什么这样设计

模型的单步计算能力是固定的，由层数和宽度决定。思维链不改变单步能力，它把一个需要很多步推理的问题，拆成一连串各自只需一小步的生成，用更多的输出 token 换更深的推理。推理模型是把这个交换内置化，并通过训练让模型学会怎样想更有效。

## 优势、劣势、什么时候不该用

**优势**：不换模型、不加外部组件，就能提高多步问题的正确率；推理过程可以留档，出错时能看到错在哪一步。

**劣势**：输出变长，费用和延迟上升；它提升的是推理，补不了知识。资料里没有的事实，想得再久也想不出来，只会编得更有条理。

**不该用的时候**：见上表右列。另外对已经内置思考的推理模型，再在提示词里规定"先做第一步、再做第二步"的固定步骤，往往多余，有时还有反作用。给出目标和约束，让它自己安排步骤更好。

## 常见误解

**"思考内容就是模型真实的思考过程。"** 思考内容是模型生成的一段文字，它对最终答案有实际影响，但它不是内部计算的完整记录。有研究显示，模型给出的理由有时并不是它得出答案的真实依据。可以拿它辅助排错，不能当作审计证据。

**"想得越久答得越好。"** 收益递减。简单问题上多想不提高正确率，只增加成本，有时还会把简单问题想复杂。

**"推理模型能减少幻觉。"** 它减少的是推理错误。知识性错误要靠篇二的技术。

**"加一句'一步一步思考'总没坏处。"** 输出要被程序直接解析时，多出来的思考文字会破坏格式。要么分区输出，要么用第 15 章的结构化输出留出一个思考字段。

## 小结

- 模型没有草稿纸，唯一的工作记忆是自己的输出；让它写出中间步骤，每一步就只需完成一小段推理。
- 推理模型把先想后答内置了，思考内容按输出计费，费用和延迟主要花在这里。
- 多步推理和高风险任务值得多想；查事实、抽取、分类不值得；用"直接答对比分步答"实测决定。
