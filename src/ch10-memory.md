# 10 记忆：短期、长期与遗忘

## 从一个问题开场

用户上周对车载助手说过："我腰不好，座椅加热以后默认开二档。"

今天他上车说："开一下座椅加热。"助手问："请问开几档？"

用户会觉得这个助手很笨。但第 2 章讲过，模型是无状态的，上周那次会话早就结束了，这一次调用里没有那句话。

让助手"记得"，意思是：**有人在上周把那句话存了下来，并且在今天把它放进了上下文。** 记忆是一套存和取的工程，本章把它拆开。

## 掰开：两种记忆的实物形态

| | 短期记忆 | 长期记忆 |
|---|---|---|
| 是什么 | 当前会话的消息列表 | 会话之外的一个存储，文件或数据库 |
| 存在哪 | 上下文窗口里 | 窗口外面 |
| 寿命 | 会话结束即消失 | 跨会话保留 |
| 容量 | 受窗口上限约束 | 基本不受限 |
| 怎么用上 | 每次调用自动带上 | 要先取出来，放进窗口，才起作用 |

最后一行是要点：**长期记忆不取出来放进上下文，对模型就等于不存在。** 模型能用的只有窗口里的内容。所以第 1 章说，记忆是一种需求，实现它的手段仍然是"改上下文"。

长期记忆里一条记录的样子：

```json
{
  "内容": "用户腰不好，座椅加热默认开二档",
  "类型": "偏好",
  "创建时间": "2026-03-02T08:15:00",
  "最近使用": "2026-03-09T08:02:00",
  "重要度": 8
}
```

## 掰开：长期记忆的三个动作

### 写：存什么

不能把每句话都存下来。"今天天气不错"存了没用，还会在日后检索时成为噪声。常见做法是在会话中或会话结束时，让模型从对话里提炼值得长期保留的内容。通常分三类：

| 类型 | 例子 | 特点 |
|---|---|---|
| 事实与偏好 | 座椅加热默认二档；常去的充电站 | 稳定，可被新说法覆盖 |
| 经历 | 上周三反馈过右前轮慢漏气 | 带时间，会过时 |
| 做事方法 | 这位用户喜欢先听结论再听原因 | 影响行为方式 |

### 取：什么时候拿什么

两种取法：

- **常驻**：把少量核心记忆每次都放进系统提示词。适合"用户叫什么、基本偏好"这类几乎每次都用得上的内容。量必须小。
- **检索**：把记忆当成一个小资料库，按当前对话内容去检索相关的几条。这就是第 5、6 章的 RAG，只是资料从文档换成了记忆条目。

也可以把"查记忆"和"写记忆"做成工具，让模型自己决定何时查、何时记，这是第 20 章 Agentic RAG 的思路在记忆上的应用。

### 改：更新与遗忘

用户今天说"以后座椅加热开一档就行"。如果只是新增一条，库里就有两条互相矛盾的偏好，检索时可能取回旧的那条。

所以写入之前要先查有没有相关的旧记忆，然后在新增、更新、删除三个动作里选一个。这一步通常也交给模型判断。

## 手算一次：该取回哪条记忆

检索记忆时，只看"和当前话题像不像"是不够的。斯坦福的 Generative Agents 研究用了三个分数相加：

**得分 = 时近度 + 重要度 + 相关度**

- **时近度**：越近用过的记忆分越高，按时间指数衰减。原文的衰减系数是每小时乘 0.995。
- **重要度**：写入时让模型打的 1 到 10 分，"吃了早饭"1 分，"腰不好"8 分。
- **相关度**：和当前对话的向量相似度。

先看时近度怎么衰减，0.995 连乘：

| 距上次使用 | 计算 | 时近度 |
|---|---|---|
| 1 天（24 小时） | 0.995²⁴ | 0.89 |
| 1 周（168 小时） | 0.995¹⁶⁸ | 0.43 |
| 1 个月（720 小时） | 0.995⁷²⁰ | 0.03 |

一个月不用，时近度基本归零。再比较两条记忆，把三项都归一到 0 到 1 后等权相加。当前用户说"开一下座椅加热"：

| 记忆 | 时近度 | 重要度 | 相关度 | 得分 |
|---|---|---|---|---|
| A：座椅加热默认二档（一周前用过，重要度 8） | 0.43 | 0.8 | 0.9 | **2.13** |
| B：今早问过空调滤芯多久换（一小时前，重要度 3） | 0.995 | 0.3 | 0.2 | 1.50 |

A 胜出。如果只看时近度，取回的会是不相干的 B。三项相加的作用是让"久远但重要且相关"的记忆仍然能被想起来。

衰减系数和三项的权重都是可调的，这里的数字用来说明机制。

## 为什么需要遗忘

遗忘听起来像缺陷，对记忆系统来说是功能：

- **防过时**："上周右前轮慢漏气"在补胎之后就不该再影响回答。
- **防矛盾**：新旧偏好并存时，旧的必须让位。
- **防噪声**：记忆越多，检索时取到无关条目的概率越高，这就是第 7 章的失败点 4。
- **合规**：用户有权要求删除关于他的记录。

实现上有三种手段：按时近度衰减让旧记忆自然沉底；定期把多条零散经历合并成一条概括；提供明确的删除入口。

## 短期记忆也要管理

短期记忆就是消息列表。第 2 章算过，它每轮都在涨。撞到窗口上限之前要做处理：

| 办法 | 做法 | 代价 |
|---|---|---|
| 截断 | 只保留最近 N 轮 | 早期信息直接丢失 |
| 摘要 | 把较早的若干轮压缩成一段摘要，替换原文 | 细节丢失，摘要本身可能出错 |
| 转存 | 把重要内容写入长期记忆，需要时再取回 | 多一套存取逻辑 |

第 21 章在 Agent 长任务的场景下展开这部分。

## 优势、劣势、什么时候不该用

**优势**：跨会话的连续性和个性化；不必每次重新交代背景。

**劣势**：
- 记错比不记更糟：一条错误的记忆会在之后每次对话里持续造成影响，而且用户看不见原因；
- 涉及个人信息，存储、展示、删除都有合规要求；
- 增加了一条可被攻击的路径，恶意内容一旦被写进记忆，就会长期生效（第 25 章）。

**不该用的时候**：每次任务相互独立的场景，例如单次的文档翻译、一次性的问答。没有跨会话的需求，就不要引入记忆系统。

## 常见误解

**"上下文窗口够大，就不需要记忆系统了。"** 窗口解决的是单次会话内的容量。跨会话的内容不存下来，窗口再大也是空的。

**"记忆就是把聊天记录全存下来做检索。"** 原始记录噪声太大。有用的记忆是提炼过的，并且会更新和淘汰。

**"模型用久了会越来越懂我。"** 权重没有变。变的是记忆库里关于你的条目变多了。换一个不带记忆库的入口，它对你一无所知。

**"记忆应该对用户不可见。"** 让用户能查看和修改关于自己的记忆，既是合规要求，也是纠错的最有效途径。

## 小结

- 短期记忆是窗口里的消息列表，长期记忆是窗口外的存储；长期记忆必须被取出来放进上下文才起作用。
- 长期记忆有写、取、改三个动作，检索时综合时近度、重要度、相关度三项。
- 遗忘是功能：防过时、防矛盾、防噪声，记错的代价高于不记。
